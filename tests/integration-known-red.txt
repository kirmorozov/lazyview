# `--skip chaos_` run of `--test '*'` in every MySQL-family job) that may still fail without
# blocking a CI run: one "<test name> #<open issue>" per line, the shape of
# tests/chaos-known-red.txt. Blank lines and `#` comment lines are ignored; the name is the test
# exactly as cargo prints it, module path included (`pinned::…`, `definitions::…`).
#
# scripts/chaos-gate.sh reads this file in that step (--label "$FLAVOR integration"): a failure
# listed here passes the step and is written to the job summary with its issue, an unlisted one
# fails it with a ::error:: naming the file to fix. So this list is the only thing between a new
# integration regression and a red job. The test still RUNS and is reported: no continue-on-error,
# no skip, no retry anywhere, and with this file empty the step is strict exactly as it stands.
#
